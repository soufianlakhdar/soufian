Common Crawl is excluded by the audit constraints, and no page could be fetched, so the verification crawler did not run. As a result, this is a DISCOVERY audit of pages that mention Gravipack. It is not a measured backlink audit. For every discovered page, the following are UNVERIFIED unless the SERP itself showed the domain: whether a hyperlink exists, its rel attribute (follow/nofollow/ugc/sponsored), its anchor text and its target host (gravipack.com, www.gravipack.com or gravipack.fr). The 'links to' column says 'unknown' in those cases. Per the seo-backlinks MUST-NOT rule, the Backlink Health Score is INSUFFICIENT DATA (0/7 factors) and no factor gets a number. The validator passed on that basis. Other limits: WebSearch is a US-based engine, not google.fr, so the rank observations are indicative only. Page titles are 'as shown in search results' and may be rewritten; i-trekkings, for example, appears as 'statistiques Matomo'. Dates come from URLs, LinkedIn activity-ID decoding (Bash) or result summaries, and dates marked '~' are inferred. Discovered so far: about 25 third-party domains mention Gravipack. ## Raw findings (with verifier verdicts)

### The audited domain gravipack.fr has no discoverable link or mention profile; all third-party equity points to gravipack.com

`domain-equity-on-com-not-fr` · Off-Page / Authority · auditor severity **High** → verifier **weakened**, severity **Medium**

**Evidence.** A search for the literal "gravipack.fr" returned only third-party pages about the brand and no page on gravipack.fr. The search summary noted that the company's own domain appears as gravipack.com. Earlier context: site:gravipack.fr returned nothing. Every third-party page whose URL or listing names a domain names gravipack.com: the Trustpilot profile is /review/gravipack.com, and the Motherbase profile surfaced for the "gravipack.com" -site:gravipack.com query. The LinkedIn result summary says the official site is gravipack.com. The only owned URLs that surfaced in 45 searches were https://gravipack.com/ and https://gravipack.com/nos-engagements/.

<https://es.trustpilot.com/review/gravipack.com> · <https://my.motherbase.ai/startup/107826-gravipack> · <https://fr.linkedin.com/company/gravipack> · <https://gravipack.com/> · <https://gravipack.com/nos-engagements/> · <https://lespepitestech.com/startup-de-la-french-tech/gravipack>

**Why it matters.** Links and brand mentions consolidate authority on the host they point to. If gravipack.fr is meant to rank, it starts with no authority. If it is an alias, it must forward cleanly, or Google may treat the two domains as duplicates and pick a canonical the business did not choose.

**SEO effect.** If gravipack.fr is not redirected, it has no PageRank flowing in, so it will not rank for competitive queries such as 'sac à dos anti mal de dos'. If it serves the same content as .com without 301s, ranking signals and crawl budget are split and the wrong host may show in results. Clean page-to-page 301s pass all the equity built up on .com and give one brand entity for knowledge-graph and AI answers.

**How to fix.** 1) Keep gravipack.com as the canonical domain, because all discovered equity is there. Keep gravipack.fr registered as a defensive alias. 2) Add a server-level, path-preserving 301 from every gravipack.fr and www.gravipack.fr URL to https://gravipack.com. Apache .htaccess on the .fr vhost: RewriteEngine On / RewriteCond %{HTTP_HOST} ^(www\.)?gravipack\.fr$ [NC] / RewriteRule ^(.*)$ https://gravipack.com/$1 [R=301,L]. Nginx: server_name gravipack.fr www.gravipack.fr; return 301 https://gravipack.com$request_uri; If .fr ever had its own URL structure, map old URLs to new ones one by one (WordPress 'Redirection' plugin CSV import) rather than sending everything to the homepage. 3) Pick one host for .com as well (www or non-www; the SERPs show both). Align WordPress Réglages > Général (Adresse web/Adresse du site), the Yoast/Rank Math canonical tags and a host-level 301. 4) Verify gravipack.fr and gravipack.com as Domain properties in Google Search Console and compare their Links reports. If .fr once hosted a separate site, use the Change of Address tool. 5) Update every owned profile (LinkedIn, Facebook, YouTube 'À propos', KissKissBankBank, Trustpilot, Les Pépites Tech, MyFrenchStartup, Decathlon seller info) to the exact canonical https URL. 6) Do not move the primary site to .fr: that would be a full domain migration that puts the existing equity at risk, for little gain in a French-only market.

**Verifier notes.** I could not re-run WebSearch: the turn's shared 200-search budget was already used up when this check started. Re-checks used this session's saved WebSearch logs (scratchpad serp-notes.md, inv.py, tables.md) plus local claude-seo tool runs. HOLDS: no gravipack.fr URL appears in any saved result, and third parties that name a domain name gravipack.com. CORRECTIONS: (1) The statement that only gravipack.com/ and /nos-engagements/ surfaced in 45 searches is misleading. This session's site: queries found about 98 gravipack.com URLs across both the apex and www hosts, and 16 URLs on a legacy subdomain, presta.gravipack.com (PrestaShop paths such as /accueil/19-sac-a-dos-gravipack-sherpa-45.html, /40-etude-scientifique-..., /59-concours-lepine-...). They also found duplicate product paths: /produit/ versus /produit-gravipack/. The equity split that evidence supports is apex + www + presta + duplicate paths inside .com, not .fr versus .com. (2) Whether gravipack.fr already 301s, parks, or serves duplicate content is pure on-site or DNS data, and the saved PSI call for gravipack.fr returned HTTP 429 with no data. If .fr already redirects, this finding has no SEO impact, so High/8 overstates it. The fix is sound (path-preserving 301; Change of Address only if .fr ever hosted the site). It should add the presta.gravipack.com legacy URLs, mapped 1:1 to their gravipack.com equivalents with 301s, and the consolidation of /produit-gravipack/ onto /produit/. 'Yoast/Rank Math' assumes WordPress: the WooCommerce URL patterns make that likely, but it is not verified.
