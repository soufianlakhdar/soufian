### Brand's official site is split across 4 hosts: gravipack.fr (no indexed pages), gravipack.com and www.gravipack.com (both indexed), and legacy presta.gravipack.com

`entity-home-fragmented` · International / Domains · auditor severity **High** → verifier **weakened**, severity **Medium**

**Evidence.** The orchestrator's site:gravipack.fr search returned 0 results. The earlier phase's inventory (inv.py / tables.md) records 98 indexed gravipack.com URLs split between apex (e.g. https://gravipack.com/, /mentions-legales/, /nos-engagements/) and www (e.g. https://www.gravipack.com/faq/, /a-propos-de-nous-gravipack-au-service-de-votre-dos/). It also records 16 legacy PrestaShop URLs still indexed on presta.gravipack.com with older positioning: 'Gravipack, le sac à dos en apesanteur qui ne fait pas mal au dos et aux épaules' (/73-gravipack), 'Sac à dos scolaire, randonnée, sport, Gravipack le meilleur sac a dos au monde' (/content/1-livraison...). The only indexed 'étude scientifique' page is on that legacy host. Carried-over evidence, not re-verified this turn.

<https://gravipack.com/> · <https://www.gravipack.com/faq/> · <https://gravipack.com/mentions-legales/> · <https://presta.gravipack.com/> · <https://presta.gravipack.com/73-gravipack> · <https://presta.gravipack.com/40-etude-scientifique-soulage-le-dos-gravipack> · <https://presta.gravipack.com/content/1-livraison-sac-a-dos-gravipack>

**Why it matters.** Google's Knowledge Graph and LLM answer engines tie an entity to one official 'home' URL that every other source agrees on. When four hosts carry different claims, signals split and AI systems can't tell which version of the facts is official. The audited domain gravipack.fr contributes nothing: no AI engine can cite a page that isn't indexed.

**SEO effect.** Brand mentions and link equity are spread across hosts. Duplicate pages compete for the same queries. AI answers may quote the legacy presta pages, with old model names (Feather, Hiking 33), 'apesanteur' wording and superlatives, as current facts. gravipack.fr earns zero visibility or citations.

**How to fix.** 1) Pick ONE canonical host, e.g. https://gravipack.com/. If .fr is meant to be the French home, choose it instead, but never both. 2) Server or Cloudflare level: 301 every gravipack.fr/*, www.gravipack.fr/* and the non-canonical gravipack.com variant to the same path on the canonical host. 3) WordPress: Réglages > Général, set 'Adresse web de WordPress' and 'Adresse web du site' to the canonical host. Make Yoast/Rank Math output a self-referencing absolute canonical. 4) Legacy PrestaShop: map each presta URL to its closest current page and 301 it, e.g. /accueil/19-sac-a-dos-gravipack-sherpa-45.html to the current Sherpa product, /accueil/21-sac-a-dos-gravipack-feather.html to the scolaire category, /40-etude-scientifique-soulage-le-dos-gravipack to a new /etude-scientifique-exosquelette/ page (see finding no-citable-evidence-page), /59-concours-lepine-... to /gravipack-le-sac-anti-mal-de-dos-prime-au-concours-lepine/. Return 410 for pages with no equivalent. Then switch the PrestaShop install off. 5) Add Domain properties for gravipack.com and gravipack.fr in Search Console and Bing Webmaster Tools. If gravipack.fr ever hosted content, use Search Console's Change of Address tool. 6) Use the canonical URL everywhere off-site: Organization schema 'url', Decathlon brand page, KissKissBankBank, Trustpilot, LinkedIn, Wikidata P856, press kit. Escalate to Critical if gravipack.fr serves its own content behind noindex or a robots.txt block.

**Verifier notes.** I could not re-run any search: the turn's shared 200-search budget was already used up when I started. Every check below compares the auditor's claims with the recorded scratchpad data (serp-notes.md, tables.md, overlap.py), which is not an independent re-verification. Confirmed in the recorded data: 98 gravipack.com URLs (40 apex, 58 www), with no single path seen on both hosts; and 16 legacy presta.gravipack.com URLs, including /40-etude-scientifique-soulage-le-dos-gravipack and the 'apesanteur' and 'meilleur sac a dos au monde' titles. Weakened for three reasons. (1) The '4 hosts' framing counts gravipack.fr as a fragment, but 0 indexed pages for site:gravipack.fr is exactly what a correct 301 from .fr to .com produces. Whether .fr redirects, is parked or serves noindexed content needs an HTTP check. (2) Apex and www URLs appearing for different paths suggests, but does not prove, missing host canonicalization. The WebSearch backend may show stale or un-normalized URLs, so `curl -I` on both hosts and a canonical-tag check are needed. (3) The only part proven from SERPs is that the presta subdomain is still indexed, and those pages are probably low-traffic. It becomes High or Critical if apex and www both return 200 without consolidation, or if .fr serves content behind noindex or a robots.txt block. Fix correction: when the PrestaShop install is retired, keep the presta host's 301 rules live at server or Cloudflare level (Google advises keeping redirects at least a year). Bing Webmaster Tools has no 'Domain property'; verify by DNS or import from Search Console.
